# LAN Party 1.3.0

The host can now run on a homelab or VPS and be controlled from a browser.
Friends keep using the desktop app.

## Web host

- New `lan-party-web` server: the same host engine as the desktop app, without
  GTK, a tray or a display server.
- Server-rendered pages for groups, services, invites, members, approvals,
  settings and a hosting guide.
- Zero JavaScript for every core flow. A small optional script adds live status
  updates over server-sent events and a copy button.
- One live host session at a time, matching the desktop app in 1.3.
- Host-only: no join flow, no relay settings, no Relay ID, no reconnect-token UI.
- The public address is edited in the web UI and saved in `settings.json`.
- The UDP app port is owned by the deployment and shown read-only, because
  Docker fixes UDP mappings at container creation.
- First run generates a strong admin password and prints it once; `passwd`
  changes it later. Passwords use PBKDF2-SHA256 with 600,000 iterations.
- In-memory sessions with `HttpOnly` / `SameSite=Strict` cookies, CSRF tokens,
  Origin checks, login rate limiting, strict response headers and an audit log.
- Optional direct TLS, or run behind Caddy/nginx with trusted-proxy support.

## Data and security

- Everything lives in one data directory beside the Compose file or runner:
  settings, groups, the password hash, host keys and the log.
- Host keys stay owner-only files (`0700` directory, `0600` files). There is no
  app-level passphrase in 1.3; encrypt the disk and backups instead.
- The container runs as a non-root UID with a read-only root filesystem,
  dropped capabilities, a PID limit and memory/CPU limits. Only `/data` is
  writable.
- The web binary does not import GTK, cgo or the relay package.

## Packaging

- Linux amd64/arm64 `lan-party-web` zips with a no-root console runner and an
  optional hardened systemd unit. No timers, no installer.
- Docker Compose with a published TCP web port and a UDP app port, `./data`
  beside `compose.yaml`, and `setup.sh` / `webctl` helpers.
- Multi-arch `ghcr.io/desynkro/lan-party-web` image, published from CI.

## Deferred

- Concurrent multi-group hosting.
- Relay support in the web host.
- Multiple admin accounts, roles or two-factor authentication.
- Built-in ACME. Use a reverse proxy or supplied certificates.
- App-level encryption of host keys.

## Upgrading

The desktop app and the web host share the engine but keep separate data
directories. 1.3 needs no data migration. Existing desktop installs are
unchanged.

See [docs/web-host.md](../web-host.md) for setup, router forwards, reverse
proxies and backups.
